## Phases

- [x] **Phase 0 (done, not a code phase) — scope decisions.** Resolved 2026-10-22, from a dedicated scoping pass (mirroring the one done before `rag_ingestion_service` was built):
  - **The 3 strategies stay genuinely separate** - genai-rag (fixed pipeline), single-agentic-rag (ReAct tool loop), multi-agentic-rag (LangGraph orchestration). Only the shared guardrail/memory/logging core (`ai/rag_core/guarded_pipeline.py` in the original) is actually common - no forced shared abstraction beyond that.
  - **platform_components overlap - real finding, narrower than the planning docs suggested.** The docs' "Support, co-located" framing is already stale: most of what they called "Support" (interview-QA, build-deployment/CI, golden-dataset, MCP tool catalog) is already ported to `hrb_platform_components` (its own Phases 1-4), just not yet deleted from the monolith. What's actually unresolved is narrower - **3 genuine orphan routes with no home anywhere**: admin-docs-sync-to-S3, request-metrics, FAQ submissions. None are retrieval-domain. **Does not block this repo** - flagged as a separate, small `hrb_platform_components` follow-up, not resolved here.
  - **`hrb_chatbot_service`'s own retrieval code stays dormant, not deleted, once each phase here is verified live** - same reversible pattern already proven for `rag_ingestion_service`'s real Lambda cutover (disable the old path, don't remove it).
  - **4-phase breakdown**, simplest-first (mirrors ingestion's own sync-before-async sequencing): Phase 1 genai-rag, Phase 2 single-agentic-rag, Phase 3 multi-agentic-rag + domain agents, Phase 4 HITL + conversations/feedback admin views.
